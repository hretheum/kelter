## 1. Executive summary

**Overall posture: strong.** The core promise of Kelter — *a deterministic kernel validates what a model proposes* — is **genuinely and structurally enforced.** The `ValidatedAction` invariant is unforgeable by construction (private fields, `Serialize` but **not** `Deserialize`, sole constructor `ActionSchema::validate`), every one of the five `.execute(` call sites receives a validated action, the journal re-validates on resume rather than trusting itself, learned facts and WASM-backend output are context-only and never authority, and every mutating/reading route is authenticated. There is **no CRITICAL finding**: no validation bypass, no secret in the tree, no double-execution on the common path, no data-loss defect. `cargo audit` reports **0 vulnerabilities** across 395 dependencies. This is a disciplined codebase whose most important safety properties hold up to adversarial reading.

**The one thing to fix before relying on it in production: a HIGH-severity durability hole** where the SQLite (production) store silently drops one paused status from the restart-resume sweep — masked by an in-memory-only test, and contradicting the code's own documented contract and ADR 0026's restart-durability claim. See §2.

**Confidence:** High on the invariant/security core (independently verified twice). Medium on durability edge cases and performance-under-hostile-peer (reasoned from source, not empirically triggered). Coverage gaps and per-dimension confidence are stated honestly in §6. This audit did NOT run a line-coverage tool and did NOT re-run the full test suite as part of every reviewer's pass (the lead ran `cargo test --workspace` = **209 passed / 50 suites / 0 failed**, and `cargo audit`, `cargo clippy -W pedantic`, `cargo tree` — raw outputs in `docs/evidence/audit-*`).

**Naming gate:** `git grep -i hermes` = **0** ✓ (confirmed). The banned pre-rename codename does not appear in any tracked file. `agentkernel` (the interim placeholder) appears only in historical logs/notes (`docs/evidence/*`, `BUILD-EVIDENCE.md`, `PHASE-1-RESULTS.md`, `CLAUDE.md`), which CLAUDE.md's hard rules explicitly permit as audit records.

## 2. ⚠ TOP FINDING (HIGH) — surface prominently

### H-1 · Production `unfinished_runs` orphans `awaiting_delegation_input` runs across a restart

- **Severity:** HIGH · **Dimensions:** 3 (durability) + 6 (honesty)
- **Evidence:**
  - `crates/storage/src/lib.rs:213` — SQLite query: `SELECT id FROM runs WHERE status IN ('pending', 'running', 'awaiting_skill_decision', 'awaiting_delegation_decision')` — **`'awaiting_delegation_input'` is missing.**
  - `crates/kernel-core/src/store.rs:146–159` — the in-memory reference store **does** include `RunStatus::AwaitingDelegationInput`.
  - `crates/kernel-core/src/engine.rs:354–356` — the engine's own doc-contract: "*`unfinished_runs` INCLUDES it — a restart re-surfaces the input request, never orphans it.*"
  - Startup resume sweep consumes `unfinished_runs()` at `crates/daemon/src/main.rs` (resume-on-boot).
- **Impact:** On a real daemon (SQLite is the default backend), a run paused per ADR 0026 (an authorized delegation whose remote entered `input-required`) is **invisible to the boot-time resume sweep**. After a daemon restart it is never re-executed and its pending-input prompt is never re-emitted onto the fresh broadcast channel → the run is silently orphaned. Data is intact (recoverable by a code fix or manual re-trigger), so this is not data-loss — but it breaks a **documented durability invariant** and directly contradicts ADR 0026 and BUILD-EVIDENCE Phase 18, which both claim "the pause survives a restart."
- **Why it was missed:** the durability test that "proves" restart-survival (`crates/a2a/tests/delegation_interactive_test.rs::interactive_pause_survives_a_restart`) uses `InMemoryRunStore`, which is correct — so the test is green while the **production** store is broken. This is the audit's clearest example of a test-masked production divergence.
- **Recommendation:** add `'awaiting_delegation_input'` to the SQLite `IN`-list; add a **SQLite-backed** test asserting an `AwaitingDelegationInput` run is returned by `unfinished_runs()` (close the in-memory-only coverage gap that hid this). Then correct the ADR 0026 / BUILD-EVIDENCE Phase 18 restart-durability claim, or re-verify it against SQLite.
- **Triage:** trivial fix (one SQL string + one test) → **smaller model or Fable**; the honesty-doc correction → Fable.
- *Independently found by the durability reviewer; verified line-by-line by the lead auditor.*

## 4. Findings by dimension

Severity key: **Critical** (bypass/secret-leak/data-loss) · **High** · **Medium** · **Low** · **Info**.

### Dimension 1 — Architecture / invariants
**Verdict: SOUND.** The central invariant is genuinely enforced (see §5). No path reaches execution unvalidated.

- **INFO · 1-a** `crates/kernel-core/src/action.rs:83–101,122–150` — `validate` does not strip/reject model-supplied reserved-prefix args (`idempotency_key`, `__a2a_depth`, `__a2a_ancestry`). Harmless today (kernel `insert`-overwrites on injection; non-A2A tools ignore lineage), but a tool honoring an `idempotency_key` it does not declare in its schema under `additionalProperties:true` could let the model pick the dedupe key. Recommend rejecting reserved-prefix keys at validation as defense-in-depth.
- **INFO · 1-b** `crates/kernel-core/src/engine.rs` (`CompositeActionSource::execute`) — routing rebuilds every source's `action_schema(Latitude::Wide)` on every execute (O(sources) schema-build per action, and routes at `Wide` even when the run's latitude differs). Cache a name→source index. Perf/robustness nit.

### Dimension 2 — Security
**Verdict: SOUND core, several defense-in-depth gaps.** Auth ordering, SSRF origin-pinning (incl. the ADR 0027 streaming path), secret handling, and the WASM sandbox are all real (see §5).

- **LOW · 2-a** `crates/model-config/src/lib.rs:212–230` + `crates/policy/src/lib.rs:105` — `set_model_config` (POST `/api/v1/config/model`) applies **no origin allowlist** to `base_url` and swaps the live oracle immediately; this also defeats the `test`-endpoint allowlist (which then trusts the configured `base_url`). Operator-config is a trusted surface by design, so not privilege escalation — but the `test` guard is largely theater while `set` is unrestricted. Apply the preset/allowlist (or a private-range check) to `set`, or drop the `test` guard's implied protection and document model egress as trusted-operator.
- **LOW · 2-b** `crates/api/src/lib.rs:531–560,580–589` — `AuthLimiter` is **process-global** and `record_success()` clears the whole failure window, so any success (normal traffic) resets the brute-force counter; and once locked, valid tokens get `429` (self-DoS). Track failures per source IP; don't let an unrelated success reset another client's window.
- **LOW · 2-c** `crates/a2a/src/lib.rs` `.json()` on card + RPC responses (≈296–302, 383–387) — reqwest `.json()` buffers the entire body unbounded; a registered hostile agent can OOM the daemon. Cap body size before deserialize. *(Related to 3-b/9-a.)*
- **INFO · 2-d** `crates/api/src/lib.rs:496–501` — `constant_time_eq` early-returns on length mismatch, leaking token **length** via timing (negligible for a fixed-format token; per-entry compare is otherwise constant-time).
- **INFO · 2-e** `crates/api/src/lib.rs:1516–1534` — WS bearer token accepted as a `?token=` query param (can land in proxy/Referer logs). Documented browser-limitation tradeoff; prefer the `Sec-WebSocket-Protocol` token trick or a short-lived ticket.
- **INFO · 2-f** `crates/a2a/src/lib.rs:219–227` — origin pin compares `scheme://host:port` strings; reqwest re-resolves DNS per dial, so a DNS-rebind between validation and dial is a residual (operator-registered host + redirects disabled bound it). Optional: pin to resolved IP or restrict to loopback/private ranges.

### Dimension 3 — Correctness / concurrency / durability
**Verdict: mostly SOUND; one HIGH (H-1, §2) + real exactly-once edge.** Plan-mode budget race is genuinely impossible; retention never prunes in-flight; `NOTE_TASK_ID`-before-side-effect holds on the reconnecting paths (see §5).

- **HIGH · H-1** — see §2.
- **MEDIUM · 3-a** `crates/a2a/src/lib.rs:1120–1121` (+ `send_message` body ≈431–444; consumed `engine.rs` ~2666/3807) — **Exactly-once gap for inline / no-task-id A2A delegations.** The durability pivot `NOTE_TASK_ID` is journaled only for a `Task` response (or a streamed id); the inline `SendOutcome::Message` path returns `COMPLETED` **without** journaling any marker. Because `send_message` never forwards `idempotency_key` on the wire (it is declared in the action schema at `lib.rs:1016` and injected into args by the kernel, but not transmitted), a crash after `execute` returns but before the `Receipt` is written → resume sees a dangling `Intent`, no `NOTE_TASK_ID` → re-dispatches with a fresh `messageId` → the remote **re-executes**. Narrow (inline-completing agents; Task-returning agents are protected by reconnect), pre-existing (predates ADR 0027). Fix: forward `idempotency_key` in the A2A message metadata, or journal a durable marker for inline completions before returning. *The `engine.rs:2645` "tool-side dedupe guarantees exactly-once" comment is inaccurate for this case.*
- **LOW · 3-b** `apps/web-ui/src/lib/events.ts:395–407` — **dead out-of-order buffer.** The comment promises seq-gap buffering, but `rest` is never populated and `pending` is always reset to `[]`; every envelope with `seq > lastSeq` is applied immediately, advancing `lastSeq` past gaps. If seq 8 arrives before 6,7 (possible under broadcast lag), 6/7 are dropped. Mostly masked by step-keyed idempotent folding, but a distinct `rejected` event could be lost. Either implement the buffer or delete the dead code and document best-effort. *(Pre-existing; not introduced by ADR 0027's progress special-case, which sits just above this block.)*
- **LOW · 3-c** `crates/kernel-core/src/engine.rs:3138–3146` vs `3266/3270` — `a2a_attempts` can be **double-counted** across a two-crash resume (a node with both a recorded delegation decision and a dangling intent). Direction is safe (over-count → may over-refuse a legitimate sibling, never over-admit), but can spuriously fail a plan. Skip the resume-arm increment when `folded.intent.is_some()`.
- **INFO · 3-d** `crates/mcp/src/extensions.rs:320` — the sole non-test panic-family site (`unreachable!()`) is provably unreachable (the guard at `:316` already excludes `Tools|Memory`). The four `panic!` at `:522/541/561/672` are inside `#[cfg(test)]` (mod at `:482`). Justified; no action. *(Cross-confirmed by 3 reviewers + lead.)*

**Verdict: SOUND, disciplined.** Zero `unsafe`, zero dead-code/unused allows, zero TODO/FIXME/HACK. Non-test unwrap discipline is genuinely strong — **no unwrap on untrusted input** (no `from_str().unwrap`, no `serde_json::from_slice().unwrap`, no network-response `.unwrap()` on production paths); hot-path JSON uses `unwrap_or_default()`/`unwrap_or_else()`.

### Dimension 8 — API / contracts
**Verdict: SOUND auth; one disclosed isolation gap.** Every mutating/reading REST route, the WS upgrade, and `a2a_rpc` call `auth_gate` before work; only `/healthz`, the Agent Card, and static assets are public. A2A conformance and SSRF containment are real.

- **LOW · 8-a** `crates/api/src/lib.rs` (list/cancel/decide routes + WS `stream_events:1540`) — **no resource-level authorization (IDOR).** Handlers bind `_principal` from `auth_gate` then discard it: `list_runs` returns all principals' runs (verified: `store().list()` unfiltered), and any token-holder can read/cancel/decide **another** principal's paused run; `stream_events` subscribes to the **global** broadcast (`kernel.subscribe()`), so any authenticated socket sees every run's proposals/prompts/results. **ADR 0018:86–88 explicitly scopes this out** ("principals are identity/attribution, not RBAC") — so it is disclosed, not a broken invariant. Flagged because named principals invite an isolation assumption the mutating routes + WS firehose do not honor. If isolation is ever claimed, scope WS + mutations to the owning principal; meanwhile state the "any principal can read/cancel/decide any run" property prominently near the principals docs.
- **LOW · 8-b** `crates/a2a/src/registry.rs:170–244` — registry `register`/`set_trust`/`remove` do read→mutate→write of the whole TOML with only the in-memory cache under a `Mutex`; concurrent operator writes can lose an update or double-insert past the `list()` collision check (TOCTOU). Operator-gated + rare. Serialize file mutations under a write-side lock and re-check collision inside it.
- **INFO · 8-c** `crates/api/src/lib.rs:1551` — WS slow-consumer maps `Lagged → continue`, silently dropping missed events (incl. delegation-ask prompts). Durable state compensates for correctness, but a live-only client can miss a prompt. Emit a "stream lagged, refetch" sentinel.

### Dimension 9 — Performance / unbounded growth
**Verdict: hot paths sound; several unbounded structures under a hostile/long-lived process.** Ledger membership is genuinely O(1); step-mode journal is bounded by `max_steps`; the broadcast channel is a bounded 1024 ring.

- **MEDIUM · 9-a** `crates/a2a/src/lib.rs:753,805,970` — **unbounded SSE reassembly buffer** in `stream_to_terminal` (ADR 0027). `buf: Vec<u8>` grows via `extend_from_slice`, drained only on `\n\n`; a streaming peer that sends bytes without a separator grows it without limit → OOM. Contradicts the ADR 0027 claim that a hostile stream "can only add notes/timeline lines." The 120s deadline bounds time, not memory. **Cap `buf` (and per-event `data`) at a sane max (e.g. 1 MiB) → reject/fallback-to-poll.** *(Cross-confirmed by 2 reviewers; introduced by ADR 0027 — my own recent code.)*
- **MEDIUM · 9-b** `crates/a2a/src/lib.rs:870–878` + `crates/kernel-core/src/engine.rs` `record_progress` — **unbounded progress-note growth per step** (ADR 0027). Every non-final SSE frame appends a durable `a2a.progress.{ordinal}` journal row with no per-step cap; a fast/hostile streaming peer can flood journal rows for a single step within the poll window (unlike step-mode growth, which `max_steps` bounds). Cap progress notes per step (drop-with-counter after N) or rate-limit advisory-progress journaling. *(Introduced by ADR 0027.)*
- **LOW · 9-c** `crates/a2a/src/lib.rs:599,670–691` — the `circuits` HashMap is never pruned; `deregister_runtime` drops the agent from `agents` but leaves its circuit entry forever. Bounded by distinct origins ever dialed (not truly unbounded), but leaks across agent churn / token rotation. Remove the origin's circuit entry in `deregister_runtime`. *(Cross-confirmed by lead + reviewer.)*
- **LOW · 9-d** `crates/mcp/src/tools.rs:456–478` — `LedgerIndex` mutex held across `.await` (file read+write inside the guard) serializes all ledger appends on one global mutex, and the per-file key `HashSet` grows unbounded over a long-lived process. Demo/durability-smoke tool, low blast radius. Shard the lock per path and bound/rotate the key set.

### Dimension 10 — Operational readiness
**Verdict: observability strong; container hardening weak.** OTel 3-signal, structured+redacted logging, log-cap (30 MB via Quadlet `k8s-file`), and graceful degradation (`/healthz`; `501` for non-runtime-mutable config; 404/405 capability-off) are all real.

- **MEDIUM · 10-a** `deploy/kelter.container:9–35` — the Quadlet unit has **no resource limits** (`MemoryMax`/`CPUQuota`), **no security hardening** (`NoNewPrivileges`, read-only rootfs, `User=`, capability drops), and **no `HealthCmd`** wiring the existing `/healthz`. `Restart=on-failure` catches non-zero exits, not hangs. ## 5. Verified SOUND — invariants confirmed real (with evidence)

These were checked adversarially (lead + reviewers, several independently) and **hold**:

1. **`ValidatedAction` is unforgeable.** Private fields (`action.rs:63–67`); sole constructor `ActionSchema::validate` (`action.rs:145`, the only struct-literal in the workspace); **`Serialize` but not `Deserialize`** (`action.rs:62`) — serde cannot mint one from wire/journal data; the only mutators (`inject_idempotency_key`, `inject_a2a_lineage`) are `pub(crate)`, post-validation, kernel-derived values. *(Lead + arch reviewer.)*
2. **All 5 `.execute(` sites receive a validated action**, and replay **re-validates** the journaled decision (`engine.rs:2110`), failing the run on schema drift rather than executing unvalidated. No plan/a2a/mcp/wasm/resilience path reaches execution unvalidated. *(Lead + arch reviewer.)*
3. **Learned facts and WASM-backend output are context-only, never authority** (`engine.rs:1916–1935`; `wasmhost` schema-gate + truncate + provenance-tag). ADR 0016 invariant holds; proven by the committed malicious-backend test.
4. **WASM sandbox is capability-by-absence** — an ungranted host import means the module cannot instantiate (`wasmhost/src/lib.rs:13–17,107–121`); fuel + 64 MiB `StoreLimits` bound each call.
5. **Governance ordering enforced in BOTH step and plan mode** — `authorize_delegation` (budget/depth/cycle) before the trust gate before every dial, incl. plan-node admission and every retry/fallback; the plan-mode concurrent budget race is **structurally impossible** (single-writer local counter, checked+incremented before spawn). *(Durability + arch reviewers.)*
6. **Trust is never self-asserted** — discovery-registered agents start `untrusted`; elevation only via operator config or a human `allow_always`.
7. **Auth on every sensitive route; no principal spoofing** (client `a2a-caller` header journaled as an untrusted label, never as identity); constant-time token compare across the token set; A2A egress origin-pinned with redirects disabled (incl. the ADR 0027 streaming path).
8. **Secrets never in tree or logs** — only a `DUMMY_KEY` test constant + `env::var` reads; OpenRouter key from env or `0600` file, never returned by the API, logged only as a masked fingerprint.
